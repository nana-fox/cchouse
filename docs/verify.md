# 验收

## 自动项：`scripts/verify.sh`

```bash
scripts/verify.sh <instance.env>                 # 只读，随时可跑
scripts/verify.sh <instance.env> --fail-closed   # 加断网测试，客机会断网几十秒
```

| 分组 | 检查 |
|---|---|
| 出口 | claude 和 root 各连测 3 次都是 `EXPECTED_EGRESS_IP`；Cloudflare 看到的国家 = `EXPECTED_EGRESS_LOC` |
| 环境与出口一致 | 出口 IP（ipinfo）的运营商 ASN = `EXPECTED_EGRESS_ASN`；时区 = `TIMEZONE` = 客机系统时区；自动设置时区关；语言 en-US、地区 en_US |
| 不该通的 | 没有公网 IPv6 地址、直连 IPv6 不通；访问不到路由器；外部 DNS 被接管成 198.18 假 IP |
| 服务与账户 | pf 启用；三个 LaunchDaemon 已加载、mihomo 运行中；SSH 禁止密码；只有 claude 一个普通用户；guest-agent 在图形用户会话运行，tart exec 使用普通用户 |
| 断网测试 | 停 mihomo 后域名和直连 IP 都不通；恢复后回到同一出口 |

说明：`curl -6` 访问域名会连到 `::ffff:198.18.x.x`（IPv4 假 IP 的映射写法），仍走 IPv4 出口，不算 IPv6 泄漏，所以脚本直接连真实 IPv6 地址来测。

ISP 代理链路偶尔超时，单次取不到出口会自动重试两次；取到的值不一致才算失败。

阻断探针只把客机内 curl 的解析失败、连接失败或超时计为阻断；SSH 失败、TLS 错误、命令不存在等均记为验收失败。
断网测试停代理前会启动 guard，确认备份就绪；恢复到预期出口后才写确认标记。
新建实例把 guard 保留在客机 `/usr/local/<TAG>/guard.sh`，部署临时目录清理后仍可验收；旧实例兼容从临时部署目录读取 guard。
断网测试停止代理前先安装退出/中断恢复处理；恢复命令失败时会提示人工通过客机桌面恢复。宿主断电、进程被强杀等不能靠退出处理保证恢复。

## 剪贴板探针的编码与证据

SSH 环境的 `LANG` 可能为空、`LC_CTYPE=C`。ex02 中，不指定编码的中文探针双向比较失败；显式使用 UTF-8 后，英文、中文四个方向测试均通过。不能仅凭旧探针判定共享通道损坏。

1. 用私有临时文件保存两端原剪贴板，不把内容打印到日志。
2. 所有读写都显式用 `LC_ALL=en_US.UTF-8 pbcopy` / `LC_ALL=en_US.UTF-8 pbpaste`；传到远端的命令也要设置，不能只设置外层 SSH 的环境。
3. 先在两端分别做本地写入、读回比较，确认探针本身正常。再用带时间戳的非敏感英文和中文测试串，宿主写 → 客机读、客机写 → 宿主读，逐项比较内容，留出同步时间。
4. 正常结束或失败时都恢复原剪贴板，删除临时文件。报告测试方向和 PASS/FAIL，不输出原剪贴板或账号内容。

`tart exec id -un` 和 GUI agent 的 running 状态只证明执行身份与服务状态；双向内容一致才是共享能力证据。使用 UU 时还多了一段主控端 ↔ 其他用户宿主的剪贴板链路，不能把宿主 ↔ 客机探针的通过外推成三端全部通过。

## 手工项（🧑 在客机桌面上看）

- [ ] 开机自动登录到桌面，没有任何首次设置引导；系统设置图标上没有红色角标
- [ ] Safari 自动打开 Network Check 页，7 项全绿，显示 "All good — you can sign in."（页面检查：出口 IP 两个来源、出口运营商、IP 所在时区、浏览器时区、浏览器语言、WebRTC 泄漏）

- [ ] 浏览器打开 browserleaks（或同类网站）：IP、时区、语言、WebRTC 都和出口一致，没有不一致提示
- [ ] 中英文剪贴板宿主 ↔ 客机双向复制正常
- [ ] （已知不满足，修之前跳过）冷启动时 pf 应早于网卡拿到 IP，现在晚约 0.1 秒，见 [architecture.md#已知限制](architecture.md#已知限制)
- [ ] 要付款的网站（如 Stripe）能打开支付页；打不开先查是不是代理商拦了（见 operations.md）
- [ ] 电脑名是通用名，键盘、单位、12 小时制符合出口所在地习惯
